# Design records

Architecture Design Records (ADRs) for DiceStats: one file per significant,
settled decision — the *why* behind the architecture, kept next to the code.

- **Naming:** `YYYY-MM-DD-short-slug.md`, dated by when the decision was made
  (date-based rather than numbered so past decisions can be backfilled from
  history in chronological order).
- **Format:** Status / Context / Decision / Alternatives considered /
  Consequences. Keep records immutable once accepted — supersede with a new
  record instead of rewriting (link both ways).
- [DESIGN.md](../DESIGN.md) stays the *current-state* architecture doc; records
  here capture the reasoning and rejected alternatives at decision time.
